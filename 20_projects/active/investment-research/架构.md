# investment-research 架构

## 系统视图

- 当前为 monorepo：`apps/web` 承载 Next.js 内部研究工作台，`apps/api` 承载 FastAPI 后端。
- 已完成 Slice 0-9：工程脚手架、资料库、产业链/公司/指标、高管校友图谱、CSV 导入、报告项目、图表数据集、审稿中心、本地 mock AI 最小辅助链路、DeepSeek Provider、发布拆分、商业化项目记录、上市公司完整版投研增强和数据源/API 接入增强。
- 支付、多租户、ToC 前台、第三方发布 API、无人发布和真实付费数据源深度集成仍不在当前已实现范围。

## 组件

- Frontend: Next.js App Router + TypeScript + Tailwind CSS + Lucide。
- Backend: FastAPI + Pydantic + SQLAlchemy。
- Migration: Alembic。
- Database: PostgreSQL schema `investment_research`，后续保留 pgvector。
- Auth: Argon2 password hash + HttpOnly Cookie JWT。
- Review: `reviews`、`review_comments`、`report_status_history` 承载审稿门禁和状态历史。
- AI: `ai_runs`、`ai_run_inputs`、`ai_run_outputs` 承载本地 mock/DeepSeek AI 运行记录和人工确认/废弃。
- Content: `content_plans`、`content_items`、`commercial_projects` 承载已审稿报告的发布拆分草稿和商业化项目线索。
- Company Research: `company_financial_metrics`、`company_report_checklists`、`valuation_snapshots` 承载公司财务指标、47 项完整度 checklist 和估值辅助草稿。
- Data Source: `data_source_providers`、`external_metric_mappings`、`data_sync_jobs`、`data_sync_logs` 承载数据源台账、外部指标映射、同步任务和同步日志。

## 数据流

- `POST /api/auth/login` 校验用户密码，签发 JWT 并写入 HttpOnly Cookie。
- `GET /api/me` 读取 Cookie 或 Bearer token，返回当前用户和角色。
- Alembic 创建 `investment_research.alembic_version`、`investment_research.roles`、`investment_research.users`。
- 前端 Dashboard 在客户端调用 `/api/me` 验证会话，未登录跳转 `/login`。
- 报告详情可以关联资料、指标和图表，并提交审稿。
- 审稿中心通过阻塞意见门禁控制报告通过状态，审稿通过不等于发布。
- AI 工作台只生成草稿/建议和运行记录，输出必须人工确认，不自动覆盖报告正文；DeepSeek key 只允许存在后端本地 `.env` 或未来密钥管理系统。
- 发布拆分只允许从 `review_approved` 报告生成 `content_items`，不会修改原报告正文；商业化项目记录只保存内部线索和收入模式假设，不处理支付或会员账户。
- 公司投研工作台从公司详情进入，读取关联的 `company_full_research` 报告、来源化财务指标、47 项 checklist 和估值辅助草稿；confirmed 财务指标必须有来源，估值草稿不得输出自动投资结论。
- 数据源模块采用 preview-first 流程：先登记 provider 和测试连接，再创建 `metric_preview` 同步任务，最后由 Admin/DataEditor 人工确认入库；确认后写入 Source、pending Metric 和 MetricSource，不覆盖 confirmed 人工数据，不回显 API key 引用。
