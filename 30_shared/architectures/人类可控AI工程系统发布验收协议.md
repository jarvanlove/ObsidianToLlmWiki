# 人类可控AI工程系统发布验收协议

## 目的

单元测试通过只能证明局部契约，不能证明人类在真实使用链路中仍然拥有控制权。稳定版发布前必须同时验证：正常工作足够低打扰，错误或高风险工作能够停下，不可信记忆不会被静默使用，既有用户工作不会被覆盖。

## 稳定版门槛

1. 跨模块场景覆盖普通修复、范围扩大、未知根因、P1 人类理解、能力候选、断点恢复、空项目、超长旧记忆、损坏上下文和自然语言项目状态。
2. read-only 请求不得创建任务；未接入治理的修改请求必须 fail closed 并说明覆盖缺失。
3. 分别运行三个一次性本地 Git 试点：全新项目、带任务前未提交改动的项目、模拟 P1 认证边界。
4. 每个试点只保存脱敏回执或状态摘要；不得使用生产凭据、生产服务、私人源码或无关业务仓库。
5. 全量回归、严格环境检查、项目会话检查、任务范围和 diff 格式全部通过后，才允许将 release channel 从候选切到 stable。

## 责任边界

- 机器验收通过不等于产品负责人批准，也不自动授权合并主分支或部署生产。
- Git 是代码权威；Wiki 保存决策、理由、证据、风险和提交定位，不复制整份代码。
- Agent 指令和项目门禁不是操作系统权限。真实生产授权必须由部署平台、账户权限和审计系统继续承担。
- 自动记忆维护失败必须显式报告；可以保留已验证的代码结果，但不得伪称长期记忆已经成功落盘。

## 发布证据

验收报告至少记录场景结果、三个试点命令、全量测试数量、严格检查结果、稳定版清单、提交哈希、远端一致性、回滚边界和未解决风险。
