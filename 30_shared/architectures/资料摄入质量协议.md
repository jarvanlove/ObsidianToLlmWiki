# 资料摄入质量协议

## 目标

资料摄入不是“生成一篇摘要”。合格摄入必须保留：

- 原始文件
- 来源笔记
- 文档地图
- 分章节笔记
- 页码 / slide / heading 引用
- 沉淀路由建议

长文档必须先生成结构地图，再生成知识页。禁止把 100 页文档压缩成一篇没有来源定位的泛泛总结。

## 产物流水线

```text
原始文件
-> 来源笔记
-> 完整提取文本 scratch
-> 文档地图
-> 章节笔记
-> 路由建议
-> 资料沉淀候选报告
-> 项目 / 个人 / 共享 / 输出层沉淀
```

## 页面职责

| 页面 | 作用 | 必须包含 |
|---|---|---|
| 来源笔记 | 原文件登记和摄入状态 | source_path、source_hash、media_type、parse_status、derived_pages |
| 文档地图 | 全文结构索引 | 来源链接、提取方式、章节索引、引用粒度、路由建议 |
| 章节笔记 | 结构化阅读单元 | 来源定位、页码/slide/heading、主题、关键概念、关键事实、流程、短摘录、待追问问题、沉淀候选 |
| 资料沉淀候选报告 | 从章节笔记生成的处理队列 | 来源章节、source_refs、推荐目标、推荐理由、下一步动作 |
| 正式知识页 | 长期结论 | 结论、证据、来源回链、适用边界 |

## 章节笔记质量字段

章节笔记不是最终知识页，但必须足够让 agent 或用户复核原文并继续沉淀。

每个章节笔记必须包含：

- 本节主题
- 关键概念
- 关键事实
- 操作步骤或流程
- 原文摘录，默认限制在 1200 字符以内
- 待追问问题
- 沉淀候选：个人 / 项目 / 共享 / 输出

如果自动提取无法识别概念、事实或流程，必须显式写出“待人工复核”，不能用空标题伪装完成。

## 引用规则

- PDF 使用 `p.N` 或 `p.N-p.M`。
- PPT 使用 `slide.N`。
- Markdown / 文本 / docx 使用 `section.N` 或 heading。
- 章节笔记可以包含短摘录，但不应复制整章原文。
- 章节笔记的摘录必须受 `excerpt_limit_chars` 约束。
- 正式知识页必须能回链到来源笔记、文档地图或章节笔记。

## 路由规则

| 内容类型 | 默认目标 |
|---|---|
| 项目事实、需求、架构、风险 | `20_projects/active/<project>/` |
| 个人长期认知、方法、偏好 | `10_personal/` |
| 跨项目可复用模式、提示词、架构经验 | `30_shared/` |
| 一次性分析、复盘、阶段输出 | `40_outputs/` |
| 原始资料和未沉淀来源 | `01_inbox/` 或项目 `sources/` |

## P0 自动化边界

当前 P0 自动化只做确定性结构化：

- 保存原文件
- 提取文本
- 生成来源笔记
- 生成文档地图
- 生成章节笔记
- 生成路由建议

它不承诺自动产出高质量最终知识页。最终知识页仍需要 agent 结合上下文、用户目标和来源证据进行沉淀。

## 资料沉淀候选

章节笔记生成后，下一步不是立刻自动写正式知识页，而是生成待审查的资料沉淀候选报告。

候选报告必须包含：

- 来源章节链接
- `source_refs`
- 来源笔记和文档地图
- 推荐目标层：项目 / 个人 / 共享 / 输出
- 推荐理由
- 下一步动作

`source_promotion_candidates.py` 只生成候选报告，不自动创建正式知识页。正式知识页必须由 agent 或用户基于候选报告和来源证据确认后再写入。

## 质量检查

`lint_wiki.py` 会报告结构化摄入问题：

- 文档来源缺少文档地图或章节笔记
- 文档地图缺少 `derived_sections`
- 文档地图的 `section_count` 与章节数量不一致
- 章节笔记缺少来源引用
- 章节笔记缺少质量字段
- 章节笔记摘录超过限制
- 章节笔记长期停留在 `已生成` 且存在推荐目标，说明存在沉淀积压
