# AI项目初始化提示词

## 使用场景

当你准备启动一个新项目，或一个已有项目还没有项目级 `CLAUDE.md` / `AGENTS.md` / `PRODUCT_SPEC.md` / `ARCHITECTURE.md` 等控制文件时使用。

## 提示词

```text
你现在要帮我初始化一个“独立开发者 AI 生产级项目”的项目控制面。

先不要写业务代码。
先阅读当前项目已有文件。如果是空项目，就基于我下面提供的信息创建项目级文档。

我的项目信息：
- 项目名称：
- 目标用户：
- 核心痛点：
- 解决方案：
- MVP 必须做：
- 当前版本明确不做：
- 技术栈偏好：
- 部署偏好：
- 数据库偏好：
- 主要风险：

请创建或更新以下文件：

1. CLAUDE.md
   - 作为 Claude Code 和兼容工具的项目入口
   - 写清项目背景、技术栈、必读项目控制文件、架构边界、禁止事项、常用命令、任务流程、完成汇报格式

2. AGENTS.md
   - 作为 Codex 项目入口
   - 明确 Codex 直接读取项目控制文件，不依赖 CLAUDE.md
   - 写清 Codex 的搜索、编辑、验证、汇报规则

3. PRODUCT_SPEC.md
   - 写清目标用户、核心问题、MVP 范围、非目标、核心用户路径、验收标准、需求变更记录表

4. ARCHITECTURE.md
   - 写清系统形态、模块边界、数据模型、API contract、权限模型、外部依赖、架构红线

5. TASKS.md
   - 建立 Now / Next / Blocked / Done
   - 每个任务必须有 ID、风险等级、验收标准、状态

6. TESTING.md
   - 写清 typecheck、lint、unit、integration、e2e、build、verify 命令
   - 如果当前项目还没有这些命令，标注 TODO，不要编造已存在命令

7. DEPLOYMENT.md
   - 写清环境、环境变量、部署步骤、数据库迁移、回滚方式

8. OPERATIONS.md
   - 写清日志、监控、常见故障、备份恢复、成本检查

要求：
- 内容必须具体到本项目，不要写泛泛原则。
- 如果信息不足，先列出最多 8 个必须确认的问题。
- 不要新增复杂工具链。
- 优先单体、简单、可部署、可测试。
- 所有文件都要服务于后续 AI 执行任务，而不是写给人看的空文档。

最后输出：
- 创建/修改了哪些文件
- 哪些信息仍然缺失
- 下一步建议做哪 3 个任务
```
